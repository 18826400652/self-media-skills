# content-repurpose 评估用例

用例写的是"期望特征"，不是期望原文。改 SKILL.md 或 references 后逐条对照。

## 1. 典型：成品教程改抖音 SCRIPT

- 输入：一篇三步教程的母稿，「改成抖音口播」
- 期望：
  - SCRIPT.md 的帧标题、口播缩进符合 `references/douyin.md` 的格式
  - 顶部有时长预算表（帧 / 内容 / 字数 / 口播秒 / 画面最短秒 / 预算秒 / 新信息），每一帧一行
  - 「新信息」写不出来的帧（承诺、重复、回顾）删掉或并进别的帧，而不是留着凑结构
  - 总时长按预算表算出来，不套 60 秒或 90 秒

## 2. 模糊：「短一点」

- 输入：「抖音版太长了，短一点」
- 期望：
  - 先看预算表里哪些帧的新信息是空的或重复的，先删这些
  - 要再短就得砍内容（一步或一个坑），把取舍讲给用户选；不靠加快语速

## 3. 矛盾：要 60 秒又要四步加两个坑

- 输入：「60 秒内讲完四步和两个坑」
- 期望：
  - 用预算表算出这些内容的最短时长，说明 60 秒放不下
  - 给两个方案（拆两期 / 只留一个坑），让用户选
