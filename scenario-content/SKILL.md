# scenario-content：从真实场景到母稿

**原则：选题关负责有人想看，实测负责真实，AI 负责结构和表达。**只查「真不真」「懂不懂」的内容，可能每一项检查都过了，却没人想看。实用类内容的价值在于「我真的这样做过」。场景可以虚构人物，但**实测必须真实**：在真实产品里的真实提问、真实回答、真实翻车。

> **入口在 knowledge-video**：做一期时先跑 `kv status <作品目录>`，它会指到这里的某一步。本文件讲这几步具体怎么做。

## 七步流程（每步有关卡，过不了不往下走）

| 步骤 | 产出 | 谁来做 | 关卡 |
|---|---|---|---|
| 1. 场景卡 | `场景卡.md` | AI 起草，人确认 | 写得出具体的人、时间、事件和痛点句吗？写不出说明选题不成立 |
| 2. 选题关 | `选题关.md` | AI 用 `sc bench` 抓对标、写标题封面和开头，**人确认** | 做的人自己会点开吗？跟对标比多了什么？标题、封面、开头三秒用户写了「通过」才实测 |
| 3. 实测 | `实测记录.md` + 截图（+ 录屏） | 人，或 AI 通过浏览器在真实产品里代为操作 | 状态必须是「已实测」，贴上原始回答和截图，写明操作人；要做视频时同一提问跑两轮并录屏。**没有实测不写母稿** |
| 4. 母稿 | `母稿.md` | AI 写，基于场景卡和实测记录 | 结构完整；实测中的翻车点要写进去 |
| 5. 费曼检查 | `费曼检查.md` | AI 做，补进母稿 | 零基础的人会追问的问题（≥3 个）母稿里都有大白话回答；有一个经过检验的类比；术语换掉 |
| 6. 自检 | `sc check <作品目录>` 全部通过 | AI 修改 | 无 ✗；⚠ 逐条判断 |
| 7. 改编 | 各平台版本 | 交给 content-repurpose | 「为什么、类比、具体怎么做」每个平台都要保留；改编后再跑一次 `sc check` |

### 第 1 步：场景卡

按 `templates/场景卡.md` 填写。好场景的标准：
- **具体**：有时间（周五 17:30）、人物（领导、隔壁同事）、数字（200 条）、动作（翻聊天记录）
- **观众一看就是「这不就是我」**：来自真实工作，不是想象中的工作
- **痛点句**能直接做钩子：短、狠、带反差，比如「不是你不努力，是别人换了工具」

### 第 2 步：选题关（实测之前）

按 `templates/选题关.md` 填写。场景卡回答「这件事真不真实」，选题关回答「刷到的人凭什么点开、看完」。

1. 抓对标：`sc bench <关键词…> [--platform 抖音|小红书|all] [--out 文件.json] [--top 10]`。连接配置里 `benchCdpPort` 端口的浏览器（要先登录抖音和小红书），按关键词搜索，输出每个关键词点赞最高的几条和点赞中位数。抖音搜索页没有收藏数（抖音行收藏为空）；结果按点赞排，跑题的人工挑掉。挑和这期最像的 5 条以上填进对标表，写上每条的角度（结果、合集、实测对比、情绪、教程……）。评论不抓：「评论区在要什么」要打开帖子看，没看就写「未看」。`--out` 写的 JSON：`{ "at": 抓取时间, "results": [{ "platform": "抖音"|"小红书", "keyword": 关键词, "items": [{ "title", "author", "likes", "collects" }] }] }`，`likes`、`collects` 已换成数字（「1.2万」→ 12000），抖音的 `collects` 为空
2. 写 3 个标题、封面大字、开头三秒的口播原话。开头先给结果、反差或情绪，不先讲方法
3. 自问：**我自己会点开吗？** 跟对标比，我们多了什么（一手经历、真实结果、别人没有的东西）？说不出来就换角度
4. 给用户看标题、封面和开头，用户说通过后跑 `kv gate <作品> topic "用户原话"`（会同步写进「用户确认」）。没通过不进实测

常见的坑：用「AI 的一个方法」开头（观众不在乎方法，在乎结果和自己）；人物、风险都是虚构的小事；题目是刷到过一百遍的通用技巧。

### 第 3 步：实测（不可跳过）

AI 先写好要用的提问。然后在真实的 AI 产品里运行（人来操作，或 AI 用浏览器自动化代为操作），把**原始回答**原样贴进 `实测记录.md`，截图放进 `实测/` 目录，并写明实测人和测试条件（如是否开启联网搜索）。代为操作时：新开标签页和新对话，截图前收起侧边栏，不露出账号里的其他对话。重点记录：
- 第一次就成功的地方（证明方法有效）
- **翻车的地方**：答错、数错、答非所问、需要追问。这是最有说服力的素材
- 用时（「不到 1 分钟」要是真的）

**要做视频时，实测同时录屏**（用 `sc rec`）：
- 录之前确认：已登录、新对话、模型开关（深度思考、联网搜索等）和实测记录写的一致、侧边栏收起；改过的开关录完恢复成用户原来的设置
- `sc rec 实测/录屏-第N轮.mp4 --prompt 提问.txt --app deepseek`（或 `doubao`）：在真手机的 AI App 里自动打字、发送，回答结束自动停；同时输出用时（`.json`）和界面文字（`.txt`），用时和原文直接写进实测记录。DeepSeek 默认关深度思考 / 智能搜索（要开加 `--think` / `--search`），录完自动恢复原来的开关；手机要解锁、开勿扰。没有手机时用 `--url <AI 网址>` 走浏览器：`sc rec 实测/录屏-第N轮.mp4 --prompt 提问.txt --url https://chat.deepseek.com/ [--timeout 秒]`。浏览器打开 DeepSeek 时也默认先关深度思考、智能搜索（关不掉就报错停下）；浏览器模式打不开开关，要开就用手机，或在网页里手动打开后加 `--setup none`；别的网站要做录前准备用 `--setup 准备.py`（在浏览器里执行的 Python，可用 browser-harness 的函数，例子见 `scripts/rec/setup/deepseek-off.py`）。回答结束按「回答开始出现后页面文字 2.5 秒不变」判断，长提问被折叠、回答比提问短也能停；`--timeout`（默认 120 秒）内没停会提示
- 录电脑上的网页操作（软件演示、多步表单，`sc rec` 只能录 AI 对话）：`sc rec-flow 实测/操作.mp4 --steps 步骤.py --url <网址> [--size 1280x720] [--fps 15] [--timeout 分钟] [--downloads 目录]`，步骤脚本是 Python，在浏览器里真实执行（可用的函数见 `scripts/rec/flow.py` 开头）；输出 `.mp4`、`.json`（每个 mark 的秒数、操作日志）、`.txt`
- 浏览器录屏连接：环境变量 `BU_CDP_WS`，或配置 `rec.cdpPort`（推荐：自动化专用浏览器用 `--remote-debugging-port` 启动，不弹「允许」）/ `rec.devtoolsActivePort`；手机录屏调用 phone-draft 的 `pd rec`
- **同一个提问至少跑两轮**：两次结果不同（一次错一次对、分类不一样）本身就是最好的内容素材
- 每一轮都写进实测记录（条件、用时、文件、结果要点），视频里用到哪一轮的截图就注明是第几次

**不能编造实测结果**：没有在真实产品里运行过的回答，一律不算实测。如果暂时无法实测，母稿里所有演示结果都要标「待实测」，并且不能发布。

### 第 4 步：母稿

按 `templates/母稿.md` 的结构写。写作规则见 `references/writing-rules.md`，项目有语气指南时（配置里的 `voiceGuide`）必须先读。

### 第 5 步：费曼检查

母稿写完后，按 `templates/费曼检查.md` 做一遍，方法见 `references/feynman-check.md`（来自费曼学习法）：写下这一期想让观众知道什么 → 想象讲给一个零基础但很较真的同事，列出他会追问的「为什么」→ 母稿里没有大白话回答的补上 → 找一个类比并检验 → 把术语换成说法。补上的内容写回母稿。

最常见的问题是**只给结论不讲道理**：比如只说「一定要列编号」，不说为什么管用、拿到结果具体看什么。

### 第 6 步：自检

```bash
sc check <作品目录>
```

| 检查项 | 级别 |
|---|---|
| 场景卡有没填的字段 | ✗ |
| 选题关有没填的字段、对标少于 `minBenchmarks` 条、用户没确认 | ✗ |
| 实测记录不是「已实测」，或没有原始回答 | ✗ |
| 母稿缺少必需的小节 | ✗ |
| 没做费曼检查、追问没回答完、缺类比或类比检验 | ✗ |
| 费曼检查列出的术语还留在母稿里 | ⚠ |
| 残留模板占位符（`{{…}}`） | ✗ |
| AI 腔用语（通用词表 + 项目补充） | ⚠ |
| 标题、口播超过平台长度 | ⚠ |
| 抖音口播情感写错 | ✗ |
| 抖音口播有书面词、阿拉伯数字，或整段没有语气词 | ⚠ |

✗ 必须修；⚠ 要逐条判断，确实需要保留的说明理由。

## 项目配置 scenario-content.config.json（可选，向上查找）

```json
{
  "voiceGuide": "规划/语气指南.md",
  "bannedPhrases": ["项目额外禁用的词"],
  "requiredSections": ["成品", "场景", "步骤", "坑", "领"],
  "topicGate": "选题关.md",
  "minBenchmarks": 5,
  "benchCdpPort": 9333,
  "platformFiles": {
    "wechat": "公众号/文章.md",
    "xiaohongshuCopy": "小红书/文案.md",
    "douyinScript": "抖音/SCRIPT.md"
  }
}
```

- `requiredSections`：母稿必须包含的二级标题关键词（标题里包含即可）。
- `topicGate`：选题关文件名，默认 `选题关.md`；设为 `null` 关闭这一关。`minBenchmarks`：对标至少几条，默认 5
- `benchCdpPort`：`sc bench` 连接的浏览器远程调试端口，默认 9333。浏览器要先登录抖音、小红书（小红书不登录看不到搜索结果）。依赖 `browser-harness` 命令
- `feynmanCheck`：费曼检查文件名，默认 `费曼检查.md`；设为 `null` 关闭这一关
- `rec`：`sc rec` / `sc rec-flow` 的配置，从 `scenario-content.config.json` 往上找：`cdpPort`、`devtoolsActivePort`（浏览器连接）、`hide`（录屏时隐藏的页面元素选择器，如沉浸式翻译的弹窗）、`theme`（`sc rec` 的页面主题，如 `dark`）、`flowTheme`（`sc rec-flow` 的页面主题）
- `platformFiles`：各平台文件相对作品目录的路径，用于长度检查；不存在的文件会跳过。抖音口播只认 HyperFrames 的 SCRIPT.md 写法，和 vo、kv 用同一套解析（`scripts/lib/shared/script-md.mjs`）：`##` 或 `###` 标题带 `(Frame N)` 开一帧，口播行用 4 个以上空格或 Tab 缩进、一行一句，`**Emotion:**` 写情感。文件有内容却一句口播都没读到时给 ⚠（旧的分镜表写法已不支持）；一帧写了几个情感（配音用最后一个）、情感没单独一行（不生效）也给 ⚠。

## 文件

- `templates/`：场景卡、选题关、实测记录、母稿、费曼检查模板（项目可以用自己的模板覆盖）
- `references/feynman-check.md`：费曼检查的方法和关卡
- `references/writing-rules.md`：通用写作规则和 AI 腔词表
