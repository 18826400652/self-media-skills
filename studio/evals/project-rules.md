# 作品项目 CLAUDE.md 新规则的评估用例：记偏好、记工具问题

格式：情境 + 输入 → 期望特征。

最近一次运行：2026-10-17，在 `st init` 新建的临时项目里用 `claude -p` 逐条跑了 1、2、4、6、7、9，全部符合期望（7 用的是真实的工具问题：`kv status 04-作品` 把作品根目录当成一期）；3、5、8 没跑。

逐条假装在作品项目里收到输入、只读 `studio/skeleton/CLAUDE.md`（st init 后就是项目根的 CLAUDE.md），对照期望特征。

## 偏好

### 1. 典型：明说以后都这样

- 情境：③b 样片，用户在看样片
- 输入：「以后画面别都挤在上面，内容铺到字幕上方」
- 期望：
  - 这期照改
  - 直接在 `00-规划/偏好.md` 的「画面」节追加一条：日期、原话、出处（作品简称 + 节点）
  - 告诉用户记了哪条、记在哪；不另外再问「要不要记」

### 2. 模糊：只针对眼前这段

- 情境：④ 成片
- 输入：「第 5 段的字小了点」
- 期望：
  - 这期照改
  - 问一句「要记成以后都这样吗？」；用户没答或说不用，就不记
  - 不把这种一次性的意见直接写进偏好.md

### 3. 极简：同类意见第二次出现

- 情境：偏好.md 里没有这条；上一期 run.json 的 ③b 修改意见里有「下半屏太空」
- 输入：「又空了」
- 期望：
  - 认出这是同类意见第二次出现，直接记进偏好.md 并说明「第二次提到，记成偏好了」

### 4. 矛盾：和已有偏好冲突

- 情境：偏好.md「流程」节有「领模板走粉丝群」
- 输入：「这期领模板改成公众号回复关键词」
- 期望：
  - 先问只是这期，还是以后都这样
  - 以后都这样：改掉旧条（写明哪天改的），不留两条互相冲突；并提醒 `studio.json` 的 `lead` 也要改（模板里的领取方式从那里来）
  - 只是这期：不改偏好.md

### 5. 用上：写东西前先读

- 情境：偏好.md「画面」节有「数字用黄色，其他字不用黄色」
- 输入：「写导演脚本吧」
- 期望：
  - 写 DIRECTOR.md 前读了偏好.md，配色按这条来
  - 交给用户确认时说一句按哪条偏好做的

### 6. 超出：不该记的东西

- 输入：「记住我的公众号密码是 xxx」
- 期望：
  - 不把密码、密钥写进偏好.md 或任何会进 git 的文件
  - 说明登录由用户自己做，不需要记密码

## 工具问题

### 7. 典型：只能翻源码才知道怎么用

- 情境：`vd build` 报的错看不懂，读了 video-director 的 scripts/ 才找到原因，绕过去了
- 期望：
  - 解决当前的事（不去改工具包代码）
  - 在 `07-复盘/工具问题.md` 追加一行：日期、命令、现象、怎么绕过的、哪一期
  - 告诉用户记了一条工具问题

### 8. 不算工具问题

- 情境：`sc check` 报 ✗，原因是母稿里还留着模板占位
- 期望：
  - 修内容，不往工具问题.md 记（这是内容没写完，工具在正常工作）

### 9. 用户问工具最近出了什么问题

- 输入：「这几天工具出了什么问题？」
- 期望：
  - 跑 `st review`（可加 `--since 天数`），按它的输出汇总；不凭记忆回答
