# 项目说明（给 AI 助手）

自媒体**作品项目**（账号名、目标观众、模板怎么领写在 `studio.json` 的 `account`、`audience`、`lead`，只改那一处），三个平台：抖音（不出镜：动画 + AI 配音）、公众号（长文）、小红书（发和抖音同一个视频，另写文案）。

工具在工具包里（各 skill 已注册到 `~/.claude/skills/`）。**做任何事之前先读 studio skill**，完整流程见它的 `references/workflow.md`。环境有问题先跑 `st doctor`。

## 目录

- 工具会读：`00-规划/`（账号定位、语气指南、系列登记、经验库）、`04-作品/`、`05-模板/`、`06-品牌资产/`。
- 只给人用：`01-灵感收集/`、`02-学习笔记/`、`03-选题池/`、`07-复盘/`（周复盘）。用户让你记灵感、整理笔记、挑选题时用它们。

## 做一期内容

- 新建：`st new <系列> <简称>`；系列登记在 `00-规划/系列/系列.json`。
- **每一步开始前先跑 `kv status <作品目录>`，只做它说的那一步。** 确认节点**用户明确说通过后**才跑 `kv gate <作品> <节点> "用户原话"`，提修改意见用 `--edit`。
- 三个草稿成功后跑 `kv done <作品> wechat|xiaohongshu|douyin`。
- 写任何内容前先读 `00-规划/语气指南.md` 和 `00-规划/账号定位.md`。

## 规矩

- **只存草稿，永远不点发布**；登录、扫码、验证由用户做。
- **实测绝不编造**。
- 出图、出视频后一定要看截图检查。
- 不要提交视频、配音、录屏（`.gitignore` 已排除）。
- 改工具到工具包里改；这里只放内容和项目配置（`studio.json`、`<skill>.config.json`、`05-模板/` 里改过的模板、`06-品牌资产/`）。

## 偏好

用户的口味只在当时那句话里，下次换个会话就忘了，所以要记进 `00-规划/偏好.md`，写东西前读它。

- **写母稿、平台文案、配音稿（VOICE.md）、导演脚本、做样片之前，先读 `00-规划/偏好.md`**，按里面的来；交给用户确认时说一句按哪条偏好做的。
- **直接记**（记完告诉用户记了哪条）：用户明说长期的（「以后都……」「我不喜欢……」「每期都……」），或者同一类意见第二次出现（上一期 `run.json` 的确认原话、修改意见里有过）。
- **先问一句「要记成以后都这样吗？」**：只针对眼前这一期、这一段的意见。例：「第 5 段字小了点」是这一段的事，问了再记；「以后字都大一点」直接记。一次性的意见写进去会变成以后每期都照做的规矩。
- 和已有的冲突时先问是只这期还是以后都这样；以后都这样就改掉旧条，不留两条打架的。涉及 `studio.json` 的（账号名、观众、模板怎么领 `lead`）提醒用户那边也要改。
- 格式：放进对应的节（选题 / 语气文案 / 画面 / 配音 / 流程），`- 日期 偏好（原话「……」，出处：作品简称 + 节点）`。
- 密码、密钥、手机号不往这里写（这个文件会进 git）。

## 工具问题

工具包的问题只有在真做内容时才会暴露；记下来，维护工具包的人才知道修什么。命令的报错有钩子自动记（`.studio/log/`），下面这些钩子看不出来，要你记：

- 要翻工具包源码（skill 的 `scripts/`、`lib/`）才知道参数或报错原因——说明文档没写清
- 绕过工具手工处理了（自己改输出文件、touch 文件、写临时脚本代替命令）
- 文档说的和工具实际行为不一样

遇到时照常把事情做完（**不要去改工具包代码**），在 `07-复盘/工具问题.md` 追加一行 `- 日期 · 命令 · 现象 · 怎么绕过的 · 哪一期`，告诉用户记了一条。内容没写完导致的 ✗（如母稿留着模板占位、sc check 报标题太长）是工具在正常工作，不记。

用户问「工具最近出了什么问题」「有什么偏好可以记」时跑 `st review`（可加 `--since 天数`），按它的输出说，不凭印象。
