# 镜头库设计：用磨好的镜头替代每期手写段画面

日期：2026-10-19
状态：设计，待用户确认
上游：`docs/superpowers/specs/2026-10-19-attention-retention-design.md`（注意力改造）、`video-director/references/visual-craft.md`（视觉工艺）
参考：[Vincentwei1021/mg-styles-15](https://github.com/Vincentwei1021/mg-styles-15)（MIT），借用它的评审标准和风格写法

---

## 1. 为什么做

### 1.1 现状

第 1 期的抖音成片（117 秒原版、85.6 秒 P0 版）都由模型每期现场写段 HTML 和 GSAP：

- **质量看这一次发挥。** 两版都是"米色纸面上一张卡片 + 宋体字"，按 mg-styles-15 的刻度大约 6 分（模板水平）。
- **出 bug 查不出来。** P0 版首帧卡片压住栏目标签、结尾"下一期"横条压住卡片，`vd qa` 0 个 ✗。
- **真东西上不了画面。** 原版录屏缩在小手机框里看不清；P0 版干脆把录屏重画成假界面。账号的差异化"程序员亲手跑过"在画面上看不到。
- **组件库用不上。** dykit 有 45 个组件，第 1 期只用了 2 个。它们是通用"页面模板"（标题页、要点页、对比页），没有统一的视觉语法，质感也只到模板级。

### 1.2 想要的

一期视频的画面 = 从镜头库里挑镜头、填内容。好看的下限由镜头库保证，不依赖某一次发挥。导演那一步只决定"这段用哪种镜头、填什么"。

**这是"用户输入 → 自动出片"能成立的前提**：用户不是设计师，没法每期把关画面；画面质量必须在建库时定好。

### 1.3 方向（用户 2026-10-19 确认）

**回形针式科普的视觉语法 × 账号自己的配色。**

- 借回形针的做法：真实素材抠图加白描边变成"贴纸"；镜头在一张大画布上平移、推近，一镜串多个信息点；大数字砸入；引线标注；每句口播带一个新画面元素；冷静、精确、信息密。
- 保留账号配色：米色底、墨黑字、荧光黄 = 重点、红 = 错的 / AI 编的（封面已固定这套，首帧要和封面对得上）。
- 综艺花字只用在全片 2–3 个重拍上。
- 不再用"一张张纸卡片摆在桌上"的画法。

## 2. 目标、非目标、反目标

### 2.1 目标

1. 建一个 **12 种镜头 + 1 种转场** 的镜头库，每种镜头经独立评审达到 **各维度 ≥7.5、平均 ≥8**（刻度见第 6 节，8 = 高端广告公司水平）。
2. 每种镜头 **换三组不同内容都好看**（短 / 典型 / 极端），不只是 demo 好看。
3. 导演脚本改成"选镜头 + 填变量"；一期里手写段 **≤1 段**，并写明理由。
4. 用镜头库重做第 1 期，整片评审分比 P0 版高（同一套评审、同一个评委设定），`vd measure` 指标不变差。

### 2.2 非目标

- 不改内容流程（选题、母稿、SCRIPT、VOICE）。
- 不做多套风格。这一版只做一套视觉语法；配色走项目 `palette`，所以换账号仍然能用（工具包与账号无关）。
- 不引入 3D、WebGL、生图 / 生视频模型。
- 不删旧的 dykit 组件；旧工程照常能 build。
- 不做发布数据闭环（另一个子项目）。

### 2.3 反目标（做到了也算失败）

- **demo 好看，真内容一填就崩**：中文字数一长就溢出、缩成小字、压字幕。
- **镜头之间撞脸**：12 种镜头看起来是同一张卡换文字，整片还是"会动的 PPT"。
- **自己做自己评**：评审能看到制作过程，或由制作的同一个会话打分。
- **再造一个假界面**：凡是"实测里真实发生的画面"，镜头必须用真实截图 / 录屏，不能画。

## 3. 约束

- **HyperFrames 规则不变**：每一帧是时间的纯函数（seek 安全）；单条暂停的 GSAP 时间线；`immediateRender: false`；现有 `director-rules.md` 第 13–17 条的坑都适用。
- **抖音版面**：内容区 x 60–1020、y 230–1150；字幕带 y 1180–1440；顶部 200、右侧 160（y 760 往下）、底部 480 留给平台界面；栏目标签全片都在左上，不能压。
- **字体**：只用现有的 Noto Sans SC / Noto Serif SC / JetBrains Mono（回形针的"粗等线大字"用 Noto Sans SC 900）。
- **时长跟口播走**：镜头的长度由所在段的配音决定（几秒到十几秒），动作锚定到 `@词`。镜头必须在 `minDuration` 到至少 15 秒之间都成立。
- **配色只来自 `palette`**：`bg`、`ink`、`muted`、`accent`、`alert`。镜头里不写死颜色值。
- **许可**：借用 mg-styles-15 的 `rubric.md`、`template.md` 写法，在用到的文件里注明出处（MIT）。

## 4. 镜头库里有什么

### 4.1 镜头清单

每种镜头对应教程类视频里反复出现的一类时刻。"现有"一列说明它替换或吸收哪个旧组件或手写画面。

| # | 镜头（id） | 什么时候用 | 画面 | 现有 |
|---|---|---|---|---|
| 1 | **原料 → 成品**（`dy-shot-transform`） | 钩子：亮成品 | 多张原料贴纸（日报、聊天截图）飞进工具，成品贴纸弹出，镜头推到成品的重点行 | 第 1 期 seg-01 手写 |
| 2 | **证据贴纸**（`dy-shot-proof`） | 展示一张真实截图 / 回答 | 真实截图抠成贴纸（白描边 + 投影），引线标注 2–4 处，镜头依次推到每处 | dy-scene-image-text |
| 3 | **录屏推近**（`dy-shot-rec`） | 演示真实操作 | 录屏铺满内容区（不套小手机框），镜头跟着 `@词` 推近到某一行，框选、点击、荧光笔 | dy-rec-phone |
| 4 | **大数字对比**（`dy-shot-number`） | 用时、花费、前后对比 | 超大数字砸入（3 小时 → 5 分钟），旧数字被划掉，单位小字 | dy-before-after、dy-stat-counter |
| 5 | **AI 答错盖章**（`dy-shot-stamp`） | 坑：AI 编了 / 写错了 | AI 回答贴纸，错的那行变红，盖章"编的"，再改成"待确认" | 第 1 期组件候选 dy-ai-wrong-stamp |
| 6 | **两遍对比**（`dy-shot-split`） | 有没有这句提示词的区别 | 左右或上下两张回答贴纸，同一位置的差异被圈出 | dy-scene-compare |
| 7 | **对话**（`dy-shot-chat`） | 发一句话给 AI、看它回什么 | 提问气泡打字 → 思考 → 回答逐行出现；可以接真实截图 | dy-chat-demo |
| 8 | **提示词卡**（`dy-shot-prompt`） | 展示这期给的提示词 / 模板 | 提示词逐条出现，关键短语荧光笔划过；可带"评论领"角标 | dy-prompt-card |
| 9 | **步骤章节**（`dy-shot-step`） | "第一步、第二步" | 大号步骤序号 + 一句话动作，画布上有步骤进度（1/3） | dy-chapter-title、dy-scene-steps |
| 10 | **清单点亮**（`dy-shot-checklist`） | 回顾三步、核对项 | 清单逐条打勾点亮 | dy-checklist |
| 11 | **花字砸入**（`dy-shot-punch`） | 全片 2–3 个重拍 | 综艺花字式大字砸入，带抖动和音效；可叠在别的镜头上 | dy-sticker-pop |
| 12 | **领取收尾**（`dy-shot-lead`） | 领模板 + 提问 | 模板贴纸 + 领取方式 + 结尾问题；和账号固定的结尾条不重复 | brand-ending、dy-end-cta |
| T | **画布平移转场**（`dy-shot-pan`） | 段与段之间 | 前一镜头和后一镜头像在同一张大画布上，镜头带运动模糊平移过去 | dy-tr-* |

### 4.2 共同的视觉语法

所有镜头遵守同一套语法，这样整片看起来是一个世界，而不是 12 个模板：

- **贴纸**：真实素材一律抠成贴纸，8–12px 白描边 + 三层投影（沿用 `visual-craft.md` 2.1）。
- **画布和镜头**：每个镜头内部有一个比画面大的画布和一个镜头层；信息点在画布上，镜头推、拉、平移去找它们，而不是元素在原地淡入。
- **引线标注**：细线 + 圆点 + 标签，标签用粗等线字。
- **字阶**：沿用 `visual-craft.md` 第 4 节（首帧 ≥96px、正文 ≥40px、比值 ≥1.6）。大数字 ≥200px。
- **颜色**：底 60 / 主体 30 / 强调 10；荧光黄只做"重点"，红只做"错的"。
- **动效**：入场 `power3.out` 0.45–0.6s，退场更快；重拍 `back.out(1.4)`；镜头移动用长缓动（`power2.inOut` 0.8–1.2s）。

这一节写成镜头库的 `STYLE.md`，每种镜头的说明卡引用它，不重复写。

### 4.3 每种镜头的交付物

一个镜头 = 一个目录，里面有：

| 文件 | 内容 |
|---|---|
| `SHOT.md` | 说明卡，照 mg-styles-15 `template.md` 的四段写：用途、节拍（按 `@词` 写 hook → 主体 → 落点）、标志特征和关键技法（可检验的数值）、变量表（含字数上限和超限时怎么办） |
| 组件 HTML | 和现有 dykit 组件同样的格式，能被 `vd build` 安装、按 `palette` 换色、按 `cues` 跟口播 |
| `fixtures/` | 三组内容：短、典型（取自第 1、2 期真实素材）、极端（最长字数、最短时长 15 秒以上的长段） |
| `review/` | 每一轮的评审结果和分数 |
| 样张 | 每组内容的关键帧截图 + 一支渲染好的样片 |

## 5. 镜头怎么用（导演这一步的变化）

### 5.1 DIRECTOR.md

机器块的 `segments[]` 里，每段写 `shot` 和 `vars`，取代现在的 `component` 或手写 HTML：

```json
{ "id": "seg-04-step2", "lines": [6, 7], "shot": "dy-shot-rec",
  "vars": { "src": "assets/rec-step2.mp4", "cues": "@一起粘进去|@发出去|@本周重点" } }
```

- 每段**必须**选一个镜头；确实没有合适的才手写，并在 DIRECTOR.md 写理由（`"shot": "custom", "reason": "…"`）。一期最多 1 段 custom。
- **叠加镜头**：`dy-shot-punch` 和单独的盖章不占一段，写在段里的 `overlays`：`"overlays": [{ "shot": "dy-shot-punch", "at": "@写错了", "vars": {…} }]`。overlay 不算 custom；全片 `dy-shot-punch` 超过 3 个，`vd qa` 报 ⚠。
- **转场**：段与段之间默认用 `dy-shot-pan`，方向由镜头库按前后两段自动交替（左右、上下），导演可以覆盖（`"transition": "none" | "pan-left" | …`）。实现方式见 5.4。
- 账号固定元素（栏目标签、字幕、结尾条）不变。

### 5.3a 缺镜头时：出现两次才磨（用户 2026-10-19 定）

镜头库里没有合适的镜头时，这一期**不当场磨镜头**，按下面走：

1. **这一期先手写**：这段写成 `custom`，在 DIRECTOR.md 写理由（"需要展示什么、为什么现有镜头都不合适"）。一期最多 1 段 custom；同一期还缺第二种时，选最接近的现有镜头凑合，也记进候选。
2. **记进候选台账**：作品项目里的 `00-规划/镜头候选.json`（`vd check` 追加，不需要手写），每条记：
   - `need`：一句话说清要展示什么（如"两份文件逐行对照，差异处标红"）；
   - `episode`：哪一期、哪一段；
   - `name`：建议的镜头名；
   - `status`：`once` / `queued` / `done` / `dropped`。
3. **第二次出现就排进磨镜头**：写新一期 DIRECTOR.md 时，先读台账；如果这期缺的需求和台账里某条是**同一类**，就不再新开一条，而是把那条改成 `queued`，记下第二期。"同一类"由导演判断：要展示的东西和画面动作一样就算，文字内容不同不影响；拿不准时记成新的一条。
4. **这一期照常出片**：第二次出现的那期仍然先用 `custom`，不等镜头磨好，不拖慢出片。
5. **这期做完后磨**：`queued` 的候选在这期复盘时提醒用户（`kv status` 在复盘那一步列出来）；用户同意后按第 7 节流程磨。三组内容里的"典型"那组，直接用这两期 custom 段的真实内容。
6. **入库后**：台账改成 `done`，记上镜头 id。之后再遇到同类需求就直接选它。用户不想做的改成 `dropped`，以后不再提醒。

只出现过一次的需求不磨：它可能再也用不上，不值得花评审成本。

### 5.4 转场：前后两段重叠

"像在同一张画布上平移过去"要求前后两段同时出现在画面上，所以 `dy-shot-pan` 不做成一个独立的转场组件，而是改段的排法：

- `assemble.mjs` 给有转场的相邻两段各延长一半重叠时长（默认共 0.6 秒），在交界处重叠；后一段的宿主层级在上。
- 每个镜头组件都接受两个变量 `enter`、`exit`（方向 + 时长），在段首、段尾按方向整体平移进出，带运动模糊。镜头内部的动作时间仍从段首算，不受重叠影响。
- 口播和字幕的时间不变，重叠只影响画面。
- `vd qa` 的截图点、`vd measure` 的窗口照常按成片时间算，不需要认重叠。`vd qa` 判断"谁压住了谁"时，重叠区间里的两段不算互相遮挡。

### 5.5 音效

镜头不自带音频文件。每个镜头在 catalog 里声明它的音效拍点（如 `dy-shot-stamp`：盖章那一拍配 `stamp`），`vd build` 把这些拍点换算成成片时间，并入现有的顶层 `sfx` 混音（同一套 `sfxDir`、人声避让、响度标准化）。导演在 `vd.sfx` 里写的同名同时刻音效，以导演的为准，不重复叠加。镜头评审看的是并入后的成片音轨。

### 5.6 截图和录屏里的位置

"推近到哪一行、标注哪几处"由导演（Claude）每期给出：看实测截图或录屏帧，读出百分比坐标填进 `vars`，和现在 `dy-rec-phone` 一样。对用户来说这一步已经是自动的。实测录屏是 1080×1920 竖屏，内容区只有 960×920，镜头一直在裁切画面，所以 `dy-shot-rec`、`dy-shot-proof` 的 `vd qa` 要在每个推近点截图，查推近后那一行字确实在画面里、字号 ≥37px。如果实际用下来坐标经常对不准，再加 OCR 自动定位（不在这一版）。

### 5.2 命令

- `vd components` 先列镜头库，再列旧组件。
- `vd build` 遇到 `shot` 走和 `component` 一样的安装和挂载流程。
- `vd qa` 照常查；另外查 custom 段数量，超过 1 段报 ⚠。

### 5.3 写在 video-director 的说明里

`SKILL.md` 和 `director-rules.md` 改为"先选镜头"；第 18 条"先找现成组件"升级为"必须先选镜头"；第 19 条"组件候选"改为"镜头候选"，走第 7 节的磨镜头流程。

## 6. 评审：怎么判断一个镜头够好

### 6.1 评审员

- **独立**：另开一个 agent，不带制作会话的上下文；只给它镜头说明卡、样片路径和三组内容的渲染结果。
- **先看再评**：按 mg-styles-15 `rubric.md` 的做法，先抽帧（每 0.5 秒一张总览、关键动作前后的连续帧、关键时刻原尺寸截图），再打分。
- 评审提示词从 `rubric.md` 改编，写成 `references/shot-review.md`，注明出处。

### 6.2 维度和刻度

刻度沿用 mg-styles-15：5 = 学生作业，6 = 模板水平，7 = 扎实的专业水平，8 = 高端广告公司，9 = 获奖入围，10 = 世界最好。"多数首版只值 5–7 分，不要手软。"

| 维度 | 看什么 | 来源 |
|---|---|---|
| 语法一致（style_fidelity） | 一眼看出是回形针式科普；第 4.2 节的语法都做到了 | rubric 原有 |
| 钩子和落点（concept_wow） | 第一个 0.5 秒有落点；有一个明确的高光时刻；收尾画面完整 | rubric 原有 |
| 动效功夫（motion_craft） | 缓动、错峰、预备和跟随、弧线、镜头移动；没有死帧和抖动 | rubric 原有 |
| 设计和字体（design_typography） | 构图、层级、网格、中文排版、配色、留白 | rubric 原有 |
| 质感（finish_texture） | 投影、描边、纹理、细节；没有色带、锯齿 | rubric 原有 |
| 声音对位（sound_sync） | 音效打在动作帧上 | rubric 原有，只看音效（配乐和人声不归镜头管） |
| 技术（technical） | 字体加载、无溢出、无穿帮、seek 安全 | rubric 原有 |
| **内容耐受（robustness）** | 三组内容都好看：字多不缩成小字、字少不空、长段不拖 | 新增 |
| **抖音版面（platform_fit）** | 不进字幕带和平台界面区；不压栏目标签；手机上看得清 | 新增 |

**过线**：每个维度 ≥7.5，九个维度平均 ≥8。三组内容分别打分，取最低的那组。

### 6.3 先校准评审员（提示词也先写用例）

按公共仓库 `standards/prompt-engineering.md` 第 4 节，评审提示词也要先有用例。拿已知作品给评审员打分，分数落在预期区间才算评审提示词可用：

| 校准样本 | 预期 |
|---|---|
| 第 1 期 117 秒原版的 seg-01、seg-06 | 5.5–6.5（模板水平） |
| P0 版的 seg-01、seg-06 | 6–7 |
| mg-styles-15 的 `19-paperclip.mp4`（作者终评 7.71） | 7–8.5 |
| 故意做坏的样本：字溢出、压字幕带、首帧空 | 内容耐受或抖音版面 ≤5，并点名指出 |

评审员给 117 秒原版打 8 分、或者认不出故意做坏的问题，就先改评审提示词，不进入磨镜头。

### 6.4 整片评审（第 2、4 阶段用）

单个镜头的九个维度里，"内容耐受"不适用于整片。整片评审：

- **维度**：去掉内容耐受，其余八个照用；另加"节奏"（镜头之间有快有慢、没有连续三段同一种镜头、全片有一个明确的高光）。
- **抽帧**：每 1 秒一张总览，加上每个 `@词` 重拍前后的连续帧和每段首尾各一张原尺寸截图；不按每 0.5 秒抽。
- **次数**：同一个评委设定独立评 2 次，取平均，减小打分的随机波动。
- **"更好"的门槛**：平均分比对照片高 **≥0.8**，并且没有一个维度比对照片低。第 2 阶段达不到这个门槛，就停下来和用户重新看方向，不进第 3 阶段。

---

## 7. 磨一个镜头的流程

每种镜头按同样的循环做，mg-styles-15 原片就是这样改了两轮：

1. **写说明卡** `SHOT.md`（四段 + 变量表 + 三组内容）。
2. **先出关键帧**：在 3–4 个关键时间点截静帧，每张都要能单独当海报看；不好看就改，还不做动效。
3. **做动效**，低分辨率预览，逐帧看最快的那几下。
4. **三组内容都渲染**，跑 `vd qa`，0 个 ✗。
5. **独立评审**（第 6 节）。
6. **按评审改**：先修所有 critical 和高影响项，至少一条是提升惊艳感的。保留上一版作为对照。
7. 回到第 5 步。**最多三轮**；三轮后还不过线，停下来把样片和评审意见给用户看，由用户决定接受、改设计还是放弃这个镜头。
8. **过线后给用户看**：三组内容的样片 + 评审分。用户确认后入库。

## 8. 分阶段

| 阶段 | 做什么 | 验收 |
|---|---|---|
| **0 准备** | 写 `STYLE.md`（第 4.2 节）；改编评审提示词；校准评审员（第 6.3 节）；准备三组内容的素材（第 1、2 期真实截图、录屏、文字）；给 `vd build` 加读本地组件库的开关（见 9.2），磨镜头时不用每轮推 GitHub | 校准四项全部落在预期区间；本地开关能装上一个改过的组件并渲染 |
| **1 四个核心镜头** | `dy-shot-transform`、`dy-shot-proof`、`dy-shot-rec`、`dy-shot-stamp`，外加转场 `dy-shot-pan`。这几种覆盖第 1 期最弱的地方：钩子、真实证据、坑 | 每个都过线；用户看过样片确认 |
| **2 用核心镜头重做第 1 期** | 用 P0 版的配音和 SCRIPT，DIRECTOR 改成选镜头；缺的镜头暂时用旧组件或 custom | 整片评审（6.4）比 P0 版高 ≥0.8 且没有维度变低；`vd measure` 最长静止 ≤4s、变化率 ≥12/分；custom ≤1 段 |
| **3 其余八个镜头** | 第 4.1 节剩下的 8 个 | 每个都过线 |
| **4 第 2 期全部用镜头库做** | 会议纪要那期 | custom ≤1 段；评审分不低于第 2 阶段的第 1 期 |

第 2 阶段是检查点：达不到 6.4 的门槛，停下来和用户重新看方向，不进第 3 阶段。

## 9. 已定的事和留给实现的事

### 9.1 用户定的

- 方向：回形针式科普语法 × 账号配色；综艺花字只用于重拍（2026-10-19）。
- 借用 mg-styles-15 的评审方法：独立评审、刻度、多轮修改（2026-10-19）。
- 缺镜头时先手写、记候选；同一类需求出现两次才磨成镜头入库，不当场磨（2026-10-19，见 5.3a）。

### 9.2 我定的（用户可以推翻）

- **镜头放在哪**：放进 dykit 组件库（`18826400652/hyperframes`），作为新的一类 `kind: "shot"`，id 用 `dy-shot-<名字>`（现有的组件名检查、目录和清单生成都认 `dy-` 开头），复用 `vd build` 现有的下载、锁版本、安装、换色流程；不在 video-director 里另建一套。
- **镜头数量**：12 种 + 1 种转场；按第 1 期的实际需要排出第 1 阶段的 4 种。
- **转场不做"整片一张大画布"**：每个镜头内部有自己的画布和镜头层，段与段之间靠前后两段重叠 0.6 秒、各自平移进出，模拟"同一张画布上平移过去"（5.4）。真做整片一张大画布要改掉"每段一个子画面"的结构，代价大，先不做。
- **叠加镜头**写在段的 `overlays` 里，不占一段（5.3）。
- **音效**由镜头声明拍点，并入现有顶层混音，镜头不自带音频（5.5）。
- **截图、录屏的位置**由导演（Claude）看图填坐标，先不做 OCR（5.6）。
- **整片评审**的维度、抽帧、次数和"更好"的门槛（≥0.8）见 6.4。
- **磨镜头时不往 GitHub 推**：第 0 阶段给 `vd build` 加一个读本地组件库（`~/hyperframes`）的开关，每轮修改在本地装、本地渲染；镜头过线、用户确认后，再按组件库现有流程提 PR 合并、锁版本。
- **过线标准**：各维度 ≥7.5、平均 ≥8，三组内容取最低。比 mg-styles-15 作者的终评区间（7.57–8.21）略高，因为镜头会反复使用，值得多磨。
- **最多三轮**：控制评审成本；超过就交给用户。
- **旧组件**：保留，不删；`vd components` 把它们排在镜头后面。
- **候选台账放在作品项目里**（`00-规划/镜头候选.json`），不放工具包：哪些需求反复出现是这个账号的事；台账由 `vd check` 追加，复盘时由 `kv status` 提醒（5.3a）。
