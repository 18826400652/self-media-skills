## 1. 问题

### 1.1 量到的事实

证据来自 `.dsh/qa-sample/抖音`：117.1 秒正片、14 帧 SCRIPT、DIRECTOR、`qa-douyin.json`、`audio_meta.json`、`caption_groups.json`，以及逐帧像素差分和 ebur128 测量。

| # | 事实 | 数值 | 说明 |
|---|---|---|---|
| 1 | 时长 / 字数 | 117.1s / 500 字（脚本）/ 4.46 字每秒 | 三步教程，14 帧 |
| 2 | 「坑」出现时间 | **75.0s**（@帮我总结成周报） | 全片最有戏的部分在 64% 处 |
| 3 | 第一段真实录屏 | **43.2s**（seg-04） | 观众第一次看到「真的」 |
| 4 | 元信息占多久 | 第 2、3 帧共 74 字 ≈ **16.6s** | 「今天教你」「一个 App 免费」 |
| 5 | 回顾 + 领取 + 提问 | 第 12–14 帧共 84 字 ≈ **18.8s** | 回顾那句基本是重复 |
| 6 | 画面变化 | 逐帧差异 <0.005 的帧占 **94.6%**；>0.02 的只有 **18 帧**；最长 **19.7s** 无变化 | 两次约 20 秒近乎静止 |

| 10 | 关卡 | 正片 `passed: true` 同时有 **25 条 ⚠** | craft 只报 warn；motion 用 DOM 签名判断 |
| 11 | 响度 | 整片 **-21.8 LUFS**，真峰值 -3.4 dB；人声 -21.7，BGM -14.3 后被压 | 比常见 -14 ~ -16 低 6–7 dB |
| 12 | 组件使用 | 45 个 dykit 组件，正片只用了 2 个 | 其余全部手写 |

### 1.2 三个缺口

1. **叙事顺序**：把「证明这件事值得看」放在 43 秒后，把「有戏的部分」放在 75 秒后；前 16.6 秒是元信息。
2. **画面运动**：整片是「会呼吸的海报」——94.6% 的帧像素级不变，没有镜头运动、没有硬切；唯一在变的是字幕。
3. **时长没有依据**：117 秒是「写到哪算哪」，不是「内容需要多长」。没有一张预算表说明每一帧为什么占这么多时间。

### 1.3 为什么不是「再补几条画面规则」

视觉工艺层已经把构图、材质、字阶、空白带、颜色做成了可测量、可报错的 7 项 craft 检查。但：

- craft 全部只报 warn，`passed` 只由 error 决定（`video-director/scripts/lib/qa-run.mjs` 第 85 行），所以 25 条 ⚠ 仍然过关；
- 「2 秒不动」用的是 DOM 签名，签名里包含文本（`video-director/scripts/lib/inspect-page.mjs` 第 78–87 行），字幕一变就算「动了」，一部 94.6% 帧静止的片子能过 motion 检查；
- 所有检查都在回答「画面对不对」，没有一个在回答「人会不会看下去」。

**结论：本文不改 craft 的六层，而是在它上面加一层「注意力」——时长预算、首帧、运动、声音。**

## 2. 目标与非目标

### 2.1 目标（调试期）

没有发布数据，所以不设完播率目标，用代理指标 + 人工测试：

| 指标 | 定义 | 现状 | 调试期目标 |
|---|---|---|---|
| 时长预算 | 每帧的预算秒数由字数、画面节拍、证据片段算出 | 没有预算表 | 每帧都有预算；总时长 = 预算之和 |
| 信息密度 | 每帧是否带来新信息；连续无新信息多久 | 2 帧无新信息（第 2、12 帧）+ 1 个互动帧（第 14 帧） | 连续无新信息 ≤10s；收尾 ≤12% 总时长 |
| 静态率 | 内容区（不含字幕带）在 2 秒窗口内几乎不变的窗口占比 | 43%（117s 正片） | 只记录，不设通过线 |
| 变化率 | 每分钟有几个内容区的可感知变化 | 待测 | ≥ 12/min |
| 最长静止 | 连续没有内容变化的时长 | 19.7s | ≤ 3s |
| 首帧 | 0.0s 最大字号 / 主体簇 / 证据元素可见 | 正片 46px；样片 0.0s 空 | ≥96px / ≥30% / 证据可见 |
| 构图分散 | 主体中心偏离中线的段占比 | 1/9 | ≥30% |
| 响度 | 整片整合响度 / 真峰值 | -21.8 / -3.4 | -14 ±1 / ≤ -1.0 |
| 钩子一致 | 封面大字 = 首帧大字 = 第一句核心词 | 三个 claim 不一致 | 同一个 claim |

**校准（2026-10-19，用 `vd measure` 量了两条成片）**：

| 片子 | 最长静止 | 变化率 | 静态率 |
|---|---|---|---|
| 117s 正片 | 12s | 11.3 次/分 | 43% |
| 13.4s 样片 | 10s | 4.6 次/分 | 91% |
| 5.3s P0 样片 | 3s | 0 次/分 | 100% |

> 5.3 秒的样片只用来验首帧和响度，不用来判断运动：太短，而且只有一个 200×100 的小印章，全画面均值会被稀释。运动指标要看整片。

结论：**静态率不设通过线**（正片 43% 已经低于原来的 50%，区分不出来）；验收改用 **最长静止 ≤3s + 变化率 ≥12/min**。静态率继续打印，只用来观察趋势。

真实数据（5 秒完播、整体完播、平均播放时长）在**首次发布后**再开始记，3 期后再定目标。

## 3. 关键决定

| 问题 | 决定 | 理由 |
|---|---|---|
| 时长 | **不设默认值**。每期写一张「时长预算表」，时长 = 每帧预算之和；预算由字数、画面节拍、证据片段推出 | 同一套模板套不同题，才会出现「117 秒」；时长应该由内容决定 |
| 结构 | 只做**冷开场教程**；步骤数由内容决定（2–4 步），不强制三步 | 用户暂不做反转 / 清单；三步不是所有题的答案 |
| 首帧 | 0.0s 必须有主体和「证据」（成品截图 / 录屏 / 对比）；`@词` 锚点不能用于首帧主入场 | 「话说一半」对首帧是反效果；首帧要画面先行 |
| 封面 | 封面大字、首帧大字、第一句核心词三者同 claim（已确认接受） | 点击承诺和第一眼必须对得上 |
| 运动 | 用**只看内容区的 2 秒窗口差分**，不用 DOM 签名 | DOM 签名把字幕变化算成运动，产生假阴性 |
| 关卡 | 新增指标全部 warn；硬门槛暂不做 | 调试期先看数据，不卡流程 |
| 声音 | 渲染后做 loudnorm（两遍），目标 -14 LUFS / TP -1.5 | 平台会压低响的，不会抬高低 |
| 数据 | 调试期只做人工测试；首次发布后再接发布记录和汇总 | 没有内容发布，就没有可用的完播数据 |

## 4. 指标定义（可复现）

### 4.1 时长预算（新增，替代「默认时长」）

每帧两个下限，取大的那个：

```
口播秒 = 字数 / 语速（先用 4.46 字/秒规划，配音后换成实测）
画面最短秒 = 每个 beat 0.6–1.0s + 证据片段实际长度 + 列表项数 × 0.8s
预算秒 = max(口播秒, 画面最短秒) + 0.2（收尾气口）
总时长 = Σ 预算秒
```

两个约束：

- **每帧至少 1 个新信息**（事实、数字、反转、证据）。纯过渡 / 纯重复的帧删掉或并进相邻帧；一段视频最多留 2 个「情绪 / 互动」帧（问句、停顿）。
- **收尾（回顾 + 领取 + 提问）≤ 总时长的 12%**。

预算表写在 `SCRIPT.md` 第一个 `## … (Frame N)` 之前（行首是 `|`，解析器会忽略；写在帧之后会把缩进行并进上一帧）：

| 帧 | 内容 | 字数 | 口播秒 | 画面最短秒 | 预算秒 | 新信息 |
|---|---|---|---|---|---|---|
| 1 | 结果 + 代价 | 35 | 7.8 | 6.5 | 8.0 | 成品、十秒、代价 |
| … | | | | | | |

### 4.2 画面变化（替代「2 秒不动」）

不再用 DOM 签名，改用**只看内容区的固定采样 + 累积差分**：

```bash
# 1fps，只取内容区（x 60–1020、y 230–1150），缩到 48×46 灰度；每帧 2208 字节
ffmpeg -v error -i <成片.mp4> -vf "fps=1,crop=960:920:60:230,scale=48:46,format=gray" -f rawvideo -
```

**字幕带（y 1180–1440）和栏目标签（顶部 200）不参与比较。** 否则字幕一变就算「动了」——这正是现在 DOM 签名的毛病。

Node 里比较 **t 与 t+2s**（相隔 2 帧），算内容区的平均绝对差 / 255：

- `diff >= 0.01`：这一秒内容区「有可感知变化」。阈值 0.01 是校准过的：0.005 会把编码噪声算进来；试过「6×6 网格取最大格」，它会把小字变化也算成运动（117s 正片会因此通过），已放弃；
- 连续 3 秒都 < 阈值 → 记为静止段；
- `static_ratio` = 静止窗口数 / 总窗口数；
- `change_rate` = 变化窗口数 / 时长 × 60；
- `longest_still` = 最长连续静止时长（秒）。

> 诊断阶段的 94.6% 是全画面对比、且把字幕算了进去；新口径只看内容区，同一部片子的数字会更高。两种口径不能直接比，基线要用 `vd measure` 重测。

> 为什么不用 scene score：它比较相邻帧、包含字幕带，还会把缓慢推镜算成「在动」。新口径只问一件事：**内容区有没有出现新的东西**。慢推本身不算信息变化，只算镜头语言。

### 4.3 首帧

在 t=0.0 和 t=0.3 各截一张，检查：

- 最大字号 ≥ 96px；
- 主体簇 ≥ 30%（沿用 craft 的 60px 邻近合并口径）；
- 至少一个带 `data-vd-proof` 的元素可见（成品截图、录屏、对比卡）。

`data-vd-proof` 是本设计新增的标记，只用于「证据类画面」，不参与 craft 的材质/字阶统计。

### 4.4 钩子一致

封面 H1（`抖音/封面.md` 的第一个 `#`）、首帧大字、第一句口播的核心词，三者是否同一个 claim。

P1 先做人工检查（写进 `qa.json` 的 `checked`），再加字符串级 warn：封面 H1 与 SCRIPT 第 1 帧的 `重点词` 至少 1 个共同关键词。

### 4.5 响度

```bash
ffmpeg -hide_banner -nostats -i <成片.mp4> -af ebur128=peak=true -f null - 2>&1 | tail -20
```

目标：I = -14 ±1 LUFS，TP ≤ -1.0 dB。

## 6. 时长从哪里来（本篇的核心）

### 6.1 两步算

1. **按帧算**：`预算秒 = max(字数 / 4.46, 画面最短秒) + 0.2`。画面最短秒里，一个 beat 0.6–1.0s，一段真实录屏按它自己的长度，列表每一项 0.8s。
2. **按内容删**：算出总时长后，逐帧问「这一帧的新信息是什么」。答不上来的删掉或并进相邻帧；连续 10 秒没有新信息就拆或删。

### 6.2 样本算一遍（500 字，实际 117.1s）

| 帧 | 字数 | 折算 | 新信息 | 处理 |
|---|---|---|---|---|
| 1 钩子 | 35 | 7.8s | 成品、十秒、代价 | 保留，但第一句改成结果前置 |
| 2 你能拿到什么 | 33 | 7.4s | 无（承诺） | **删**，并进第 1 帧 |
| 3 准备 | 41 | 9.2s | 工具、免费、四条要求 | **并进第 1 帧的后半句** |
| 4–9 三步 | 191 | 42.9s | 每步一个做法 + 一个结果 | 保留；步骤数按内容定 |
| 10–11 坑 + 避开 | 116 | 26.0s | 编数字、改提示词 | 保留，提前 |
| 12 回到成品 | 30 | 6.7s | 无（重复） | **删**，用画面代替 |
| 13 领模板 | 34 | 7.6s | 模板 | 压到 20 字 |
| 14 提问 | 20 | 4.5s | 无（互动） | 保留（互动帧） |

删掉第 2、3、12 帧，压第 13 帧，钩子收紧到 20 字后：**379 字 ≈ 85s**；再把第 5、7 帧和坑那帧各删 10–15 字（去掉重复解释），**约 344 字 ≈ 77s**（含气口约 80s）。

**结论**：这条内容按「讲完即止」大约是 75–80 秒，不是 117 秒，也不是 60 秒。要压到 60 秒，必须砍掉一步或砍掉坑——那是内容取舍，不是排版取舍。预算表的作用就是把这个取舍摆到桌面上。

### 6.3 段落顺序与比例（不绑定秒数）

| 段落 | 约束 |
|---|---|
| 钩子 | ≤ 3 秒；第一句给结果 / 代价；首帧同时有证据和 ≥96px 大字 |
| 承诺 + 埋 loop | 紧接钩子，不超过 3 秒；一次给全「几步、最后一步防什么」 |
| 步骤 | 2–4 步，由内容定；每步至少一个真实录屏或结果对比，每步至少一个数字 |
| 坑 + 修正 | **预告在前 10 秒**（一句话，不解释）；**揭晓不晚于 70%** 总时长；揭晓之后不再引入新步骤 |
| 收尾 | ≤ 12% 总时长；回顾只留一句，不重复步骤 |

> 不设「全片必须在 60–75 秒」的规则。时长是预算的结果，不是目标；唯一硬约束是「每帧有新信息」和「连续无新信息 ≤10 秒」。

## 8. 测试与验证

### 8.1 自动

- `vd measure` 的窗口计算：用固定 fixture（前 4 秒静止、中间 2 秒出现一个新元素、最后 2 秒硬切）验证 static_ratio / change_rate / longest_still；
- **慢推不算变化**：只有 push-in、没有新元素的 fixture，仍判为静止；
- **字幕不算运动**：只有字幕在变、内容区不动的 fixture，必须判为静止；
- **内容区之外不算**：字幕带里出现 / 消失的元素不影响结果；
- 预算表：缺表、缺新信息列、总时长偏差 >20%、收尾 >12% 各一个用例；
- 首帧检查：用 117s 正片（应报 warn）和 hero 样片（应通过）两个 fixture；
- beat 检查：缺 `data-vd-beat`、元素不可见、box 不变三种情况各一个用例；
- 响度：一个 -21.8 LUFS 的 fixture，标准化后落在 -14 ±1；
- 兼容：没有新标记的旧工程只提示，不崩。

### 8.2 人工（调试期的主力）

- **3 人测试**：找 3 个目标观众（同事 / 朋友即可），做三件事：
  1. 只看前 3 秒，问「这个视频要给你什么」——答不出就是钩子失败；
  2. 看完，问「三步是什么」「哪一步最容易错」——答不出就是结构失败；
  3. 问「会不会收藏 / 转给同事」——不愿意就是价值不够。
- **静音测试**：关声音看一遍，故事是否成立；
- **0.5 秒测试**：停在第一帧，能否看出「这视频要给我什么」；
- **截图测试**：有没有一屏值得被截图（收藏动机）。

### 8.3 数据（首次发布后启用）

- 每条视频发布后 24h / 7d 回填：5 秒完播、完播率、平均播放时长、点赞、收藏、评论；
- 3 期后再定目标、再比较「钩子类型 × 5 秒完播」；
- 单期涨跌不下结论，至少 3 期同结构对比。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 预算表变成形式主义 | 数字填了，内容没删 | 审查只看一件事：每帧的新信息是什么；答不上来就删 |
| 时长被压到信息不足 | 收藏 / 评论掉 | 预算是「删没信息的」，不是「删证据」；证据片段有最低长度 |
| 硬门槛卡住 kv | 流程走不下去 | 本期全 warn；升级条件写进 P2 的暂缓项 |
| camera 缩放触发安全区误报 | `vd qa` 出假 ✗ | 缩放 ≤1.05 + 内容内缩 4%；品牌层不参与缩放 |
| loudnorm 二次编码 | 画质损失 / 耗时 | `-c:v copy` 只处理音频；两遍测量只跑音频 |
| 调试期没有真实数据 | 无法验证「完播」 | 用 3 人测试 + 代理指标；首次发布后再接数据 |
| 模板化导致跨期同质 | 观众疲劳 | P2 的 3 套视觉世界 + 每期一个「视觉动词」 |

## 10. 开放问题

1. 3 人测试找谁？需要是目标观众（上班族 / 小店老板），不能全是同行。
2. 第一期准备发在哪个平台？抖音首发还是视频号？这决定 5 秒完播的口径。
3. 预算表的「新信息」列，用一句话写还是关键词？建议一句话，审查时能直接读出取舍。
4. 视觉世界模板（P2-4）是否等第一期发布后再做？现在做容易和内容节奏打架。

## 11. 附：按预算算出来的一个版本（示例，不是标准）

按 4.46 字/秒折算，口播约 330 字，加上气口约 75 秒。换成别的题目，秒数会变，下面的顺序和约束不变。

| 时间 | 口播（大意） | 画面 | 动作 |
|---|---|---|---|
| 0–3s | 「这份周报，我一个字没写。」 | 周报全屏（真实截图），左上角「周五 17:40」 | 大字 104px 落在截图上方；截图从 1.0 推到 1.04 |
| 3–6s | 「手机丢给它五天日报，十秒出。」 | 手机 + 五张便利贴飞入 | 便利贴逐张飞入（@五天日报） |
| 6–9s | 「但第一次，它把我坑了。」 | 周报上一行变红 | 红框 + 盖章（@坑，重拍 1） |
| 9–12s | 「三步，最后一步防它编。」 | 三步缩略图（1/2/3） | 三个数字逐个 pop |
| 12–24s | 第一步：每天三行日报 | 一张便利贴写三行，手写感 | 三行逐行出现（@做了什么/@有数字/@卡在哪） |
| 24–38s | 第二步：周五一起粘进去 | **全屏真实录屏**（不要塞进手机框） | 框选提示词 → 点发送 → 回答出现（3 个 cue） |
| 38–48s | 第三步：交前扫一眼数字和「完成」 | 周报全屏，放大镜扫过 | 两处荧光笔 + 圈出「完成」 |
| 48–58s | 坑：它把两篇写成六十赞 | 错误回答全屏 + 对比便利贴 | 红戳「编的」→ 改成「待确认」（@待确认，重拍 2） |
| 58–68s | 「日报没写的不要补」 | 提示词卡（一屏四行，完整可见） | 第 3 行逐字打出 + 高亮 |
| 68–75s | 「模板在评论区，你写周报最头疼哪块？」 | 周报 + 便利贴一摞 | 结尾条：下一期 + 问题 + 评论引导 |

这张分镜满足：0.0s 有证据、坑的预告在 6s、揭晓在 64%（<70%）、真实录屏全屏、每 10 秒有变化、收尾 7 秒（9.3%）。

## 12. 交付顺序（一句话版）

**P0 先算时长预算、删没信息的帧、首帧放证据、混音到 -14；P1 把预算 / 首帧 / 运动 / 钩子一致变成 warn；P2 等首次发布后再做内容原型和数据闭环。**

不要反过来：先做工具、再验证内容，会在错误的叙事结构上把画面做得更精致。
