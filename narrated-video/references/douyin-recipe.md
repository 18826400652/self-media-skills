# 分镜配方：AI 实测类竖屏短视频（30–40 秒）

适用于「我用 AI 做了某件事，结果怎样，你该怎么用」这一类内容（工具技巧、实测翻车、提问方法）。
这套结构来自实际对比：同一期做了 50 秒动画版和 26 秒「录屏 + 两轮实测」版，后者更抓人；再按费曼学习法补上「为什么、类比、怎么做」，成为现在的 10 帧（第 1 课，34.6 秒）。核心有四条：

1. **冲突放在开头**，不铺垫场景和常识；
2. **真实操作画面**（录屏）代替文字卡片，「讲」变成「看」；
3. **证据可追溯**：数字、截图、原话都来自实测记录，画面上注明是第几次实测、是否倍速；
4. **讲道理**：用大白话解释为什么、给一个类比、说清具体怎么做（来自费曼检查）。

## 结构：10 帧左右，一帧一句口播

| # | 段落 | 口播要做的事 | 画面（帧模板） | 时长 |
|---|---|---|---|---|
| 1 | 钩子 | 一句话抛出冲突或反常识的**结果** | 录屏压暗铺底 + `Kit.compare` / `Kit.number` 把结果摆出来 | 3–4 秒 |
| 2 | 操作 | 我怎么做的（一句话） | 录屏原速：粘贴、发送（`rec` + `chip`） | 2–3 秒 |
| 3 | 结果 | 快 / 准 / 惊喜的点 | 录屏加速 + `timer` 计时（注明倍速和真实用时） | 3–4 秒 |
| 4 | 翻车 / 细节 | 指出问题在哪，用数字说清后果 | `Kit.shot` 截图推近 + 手绘圈 | 3–4 秒 |
| 5 | 反转 / 对照 | 第二次怎样、换个问法怎样 | `Kit.shot` 第二张截图 / `Kit.compare` | 2–3 秒 |
| 6 | **为什么** | 用大白话解开开头的悬念（来自费曼检查） | `Kit.compare`：「你以为… / 其实…」，或 `Kit.chain` 原因 → 过程 → 结果 | 4 秒 |
| 7 | **类比** | 一个人人见过的东西（来自费曼检查） | **手写小动画（推荐，见下）**；来不及就用 `title`：「打个比方」+ 两三行大字 | 4 秒 |
| 8 | 方法 | 一句能照做的结论，挂上类比 | `Kit.marker` + `lead` | 3 秒 |
| 9 | **怎么做** | 拿到结果具体看什么、做什么 | 实测截图上圈出要看的地方（`Kit.shot` + ①②），或 `Kit.checklist` / `Kit.steps` | 4 秒 |
| 10 | 收尾 | 模板在评论区 + 关注 | `Kit.template`（footer 带关注） | 4 秒 |

6、7、9 三帧来自母稿的费曼检查（scenario-content 的 `费曼检查.md`）：观众会追问的「为什么」、类比、具体怎么做。**不能只给结论**，这三帧是让人记住、照做的关键。时间紧时 6 和 7 可以合成一帧，但 9 不能删。

没有翻车的选题：4–5 换成「关键提问技巧在哪 / 换个问法的对比（`Kit.compare`）」。

## 关键镜头：手写小动画

整片大部分帧用帧模板（统一、省事），但**最需要「看懂」的一两帧**（通常是类比，有时是钩子）值得做成一段小动画：把比喻演出来，而不是写成字。第 1 课的对比：「只报总价的收银员」三行大字 vs 收银台屏幕只亮一个总价 + 大问号、带编号的小票打印出来并标出重复的两行，后者明显更好懂、更好看。

怎么做：
1. 在 STORYBOARD 里删掉这一帧的 `- build:` 行，`scene` 写清楚动画脚本（每个口播词出现什么）；`nv hf-frames` 不会覆盖没有 build 的帧
2. 手写 `compositions/frames/NN-*.html`：结构照抄帧模板生成的文件（根元素和它的抗锯齿样式、底色 clip、角标、`cues.js` + `kit.js`、`var C = …Kit.cue…`），颜色只用 `var(--kit-*)`
3. 动画规则不变：每个元素在说到它时出现（`C("词")`）；只有一个亮点动作；落定后静止；不回弹
4. 能用组件的部分直接用：`Kit.receipt`（打印小票）、`Kit.number`（数字滚动）、`Kit.marker` 等
5. `nv hf-build --motion` 看入场 / 中段 / 落定，`check` 必须 0 错误（会查文字重叠和对比度）

注意：
- 类比里的物品、金额是**示意**，不是实测数据；不要和实测数字混在同一个画面里让人误会
- 右侧 160px 是抖音按钮区，标签、箭头不要伸进去
- 一个视频最多 2 帧手写，其余用模板，保持整片风格统一

范例：第 1 课 `抖音/compositions/frames/07-receipt.html`（收银台）、`08-number.html`（`Kit.receipt` 小票）。

## 画面规则（每帧都要过）

借鉴 [chenyuxiaojin/cyxj-hyperframes](https://github.com/chenyuxiaojin/cyxj-hyperframes)（MIT）的硬约束和动效笔记、[nutllwhy/hyperframes-motion-library](https://github.com/nutllwhy/hyperframes-motion-library)（MIT）的导演规则，按我们的竖屏口播改写：

1. **画面是口播的延伸，不是字幕的翻译**：字幕已经在下面了，画面不要再把这句话原样写一遍。先问「这句话里的关键词长什么样」：「只报总价」→ 收银台屏幕只亮一个数；「列编号」→ 一张带编号的小票；「两次不一样」→ 两个结果并排。实在没有形象，才用大字（`title` / `marker`），且只写关键词，不写整句。
2. **不加口播和实测里没有的信息**：画面上的每个字、数字都要在口播或实测记录里找得到；不为了「填满」临时编小标题、编数据。
3. **内容铺开**：落定时主体要铺满内容区（角标以下、字幕带以上），不要全挤在上半屏、下面空一大块。`nv hf-build --snap` 会量每帧的铺开程度，纵向不到 55% 的帧给出警告；处理办法：放大字号、把元素往下排开，或加一个和口播有关的图形（不是装饰）。
4. **落定后静止，不做退场**：元素在帧结尾前不淡出、不飞走，切换交给帧间转场；否则观众会看到「东西没了」的空画面。
5. **重点时刻一起命中**：每帧只有一个亮点动作（圈、划、数字落定、问号落下），它要和口播的那个词、音效在同一时刻（`C("词")` 对齐）；不要一个词拆成好几拍慢慢出。
6. **不剧透**：钩子只抛冲突和结果，不提前展示后面的方法、模板；方法帧之前不出现方法里的字。

另外，帧模板、组件和字幕的根元素都开了中文灰度抗锯齿（`-webkit-font-smoothing: antialiased; text-rendering: optimizeLegibility`），手写帧要照抄。

## 节奏、转场和镜头

学自官方发布视频的源码（[heygen-com/hyperframes-launches](https://github.com/heygen-com/hyperframes-launches)，Apache-2.0）：pr-to-video-launch（30 秒 10 个场景全部硬切）、claude-paper-launch 的 FRAME 规范、hyperframes-launch 的分镜和交接记录。

1. **默认硬切**：帧和帧之间直接切，靠每帧自己的入场动画接上。转场整片最多两三处，只放在**剧情转折**（「可第一次……」用 `push-slide`）和**收尾**（`crossfade`）。不要每帧都加转场，否则节奏会变得拖沓。
2. **长短交替**：大部分帧 3–4 秒，转折前后可以插一个 **1 秒左右的冲击帧**：一句话、居中、大字（`title` 加 `"center": true`），例如「两次不一样」「可它算错了」。官方用 0.9 秒的一行字把节奏拉紧。冲击帧要有自己的一句短口播。
3. **开场就在动**：第一帧第 0 秒就有东西在动（录屏在播、元素正在进来），不从空画面淡入。
4. **静态帧缓推**：落定后只剩文字和卡片的帧加 `"camera": "push"`（整帧 4 秒推近 4%，角标不动），画面不死板，观众也察觉不到「在动」。录屏帧和带 `Kit.shot` 推近的帧不用加。
5. **版面别一直靠同一边**：官方规定连续最多两帧用同一种构图（靠左 / 居中）。我们的帧大多靠左上；冲击帧、结论帧可以用居中打破。
6. **一眼主次**：眯眼看，最重要的元素要比第二重要的大 3–6 倍；两个东西一样大，就降一个。
7. **结尾呼应开头**：收尾帧可以回到开头的画面或那句话（官方是镜头拉回第一幕的画布），让人有「讲完了」的感觉。
8. **结尾不闪黑**：官方踩过子画面时间轴比分配时长短、结尾闪黑的坑。我们的版本（0.8.119）以帧时长为准，第 1 课逐帧查过没有黑帧；`nv verify` 也会查长于 0.5 秒的黑屏。

## 口播

- **钩子句式**（选一种，写成口语）：
  - 结果反差：「同一个问题，我问了 AI 两遍，两次答案居然不一样。」
  - 速度反差：「两百条反馈，AI 八秒钟就分好类了。」
  - 翻车：「AI 信誓旦旦说不会错，结果还是错了。」
- 每句 ≤ 28 字；数字写汉字；多用「可」「结果呢」「所以啊」这类转折词；不自我介绍
- 情感：钩子惊讶、翻车惊讶、结果和收尾开心、方法平静
- 语速 1.15 倍（`nv hf-audio . --speed 1.15`）；整条 30–40 秒

## 实测和素材（先于写稿）

1. 在真实产品里跑实测，用 `nv rec` 录下全过程，用时和页面全文写进实测记录
2. 关键结果截图（推近要看清的那一块，必要时先裁剪）
3. 同一个提问**跑两次**：结果不同本身就是好素材（「两次不一样」比「一次正确」更有话说）
4. 视频里出现的每个数字、截图、原话，都要能在实测记录里找到

## 帧模板（STORYBOARD 里写 `- build:`）

每帧在 STORYBOARD.md 写一行 JSON，`nv hf-build` 会自动生成画面（`nv hf-frames`）。时间写 `"@词"`（说到这个词时），不手写秒数。

```text
- build: {"rec":{"mediaStart":4.0,"rate":1.5,"dim":true},"kit":{"name":"compare","opts":{"bad":{"tag":"第 1 次","text":"合计 22 条"},"good":{"tag":"第 2 次","text":"合计 20 条"},"at":["@两遍","@不一样"],"size":72}}}
- build: {"rec":{"mediaStart":0.9,"chip":"DeepSeek 实测录屏"}}
- build: {"rec":{"mediaStart":3.3,"rate":2.4},"timer":{"value":8.7,"note":"实际用时 · 视频 2.4 倍速"}}
- build: {"kit":{"name":"shot","top":540,"opts":{"src":"assets/a.png","size":[1610,800],"caption":"第 1 次实测","zoom":{"x":1000,"y":190,"scale":2.2,"at":0.1},"marks":[{"x":1045,"y":283,"at":"@两遍","label":"又算了一次"}]}}}
- build: {"lead":{"text":"它的合计 → 我给的条数","top":600},"kit":{"name":"strike","top":720,"width":"auto","opts":{"from":"22 条","to":"20 条","inAt":"@二十二","at":"@可我","size":170}}}
- build: {"kit":{"name":"marker","top":640,"opts":{"text":"一定让它列编号","key":"列编号","inAt":"@一定","at":"@列编号","size":130}},"lead":{"text":"错没错，一眼就能看出来","top":860,"at":"@错没错"}}
- build: {"kit":{"name":"template","top":480,"opts":{"title":"提问模板 · 截图保存","lines":["你是一名【你的岗位】。"],"at":0.05}}}
- build: {"title":{"label":"下一课","lines":[{"text":"为啥 AI 写方案，","at":"@为啥"},{"text":"总是**一堆废话**？","at":"@总是"}]}}
- build: {"ground":"accent","lead":{"text":"DeepSeek 原话","top":440},"kit":{"name":"stream","top":520,"opts":{"text":"……","at":"@说好"}}}
```

可用部件（可组合，按需写）：

| 部件 | 作用 | 参数 |
|---|---|---|
| `rec` | 录屏，放在角标下方 | `src`（默认 assets/rec.mp4）、`mediaStart` 从录屏第几秒开始、`rate` 倍速、`dim` 压暗、`chip` 左上标签 |
| `timer` | 录屏上的计时面板 | `value` 真实用时、`unit`、`note`（写明倍速） |
| `kit` | 一个组件 | `name`（strike number marker annotate shot stream prompt arrow compare template checklist steps chain）、`top`、`width`（默认 960，`"auto"` 不限宽）、`opts` 见 hf-kit.md |
| `lead` | 一行灰色说明 | `text`（`**词**` 强调色）、`top`、`at` |
| `title` | 大字标题 | `label`、`lines`（字符串或 `{text, at}`）、`top`、`center`（居中，冲击帧用） |
| `camera` | 镜头 | `"push"`：整帧缓慢推近，给落定后的静态帧用 |
| `ground` | 底色 | `"accent"` = 整屏强调色（翻车帧，整片最多一次） |

录屏的 `mediaStart`：看 `nv rec` 输出的 `.json`，`sentAt` 是发送时刻、`doneAt` 是回答结束。原速播「粘贴 + 发送」从 `pastedAt - 0.6` 开始；加速播「输出过程」从 `sentAt` 开始，`rate ≈ (doneAt - sentAt) / 这一帧时长`。

表里放不下的画面，删掉这一帧的 build 行，手写 `compositions/frames/` 里的文件（`nv hf-frames` 不会覆盖没有 build 的帧）。

## 检查清单（渲染前）

- [ ] 前 3 秒就有冲突或结果，没有自我介绍、没有常识铺垫
- [ ] 开头的悬念在后面解开了（为什么），有类比，有「具体怎么做」
- [ ] 至少一帧是真实操作录屏
- [ ] 倍速播放的地方注明了倍速，计时显示真实用时
- [ ] 每个数字、截图、原话都能在实测记录里找到；不同次实测的截图注明是第几次
- [ ] `snapshots/sheet.jpg` 每帧看过：角标每帧同一位置、文字不压在录屏文字上、不进字幕带和右侧按钮区
- [ ] `--snap` 没有「下半屏偏空」警告；画面没有把字幕原样再写一遍；画面上没有口播和实测里找不到的信息
- [ ] 结尾承诺了「评论区有模板」，发布记录里写好了置顶评论原文
