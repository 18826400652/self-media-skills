# 分镜配方：AI 实测类竖屏短视频（聊天版，默认 2 分钟左右）

适用于「我用 AI 做了某件事，结果怎样，你该怎么用」这一类内容（工具技巧、实测翻车、提问方法）。

**2026-10-07 起默认是聊天版**。之前的「1 分钟、能用 → 用好三招 → 避坑」（70 秒塞七八个点，一点一句）观众看不懂：讲的东西多，每个都没讲透，还冒出观众不认识的人名和实测细节。现在的原则：**不卡时长，先讲清楚；一条视频只讲透一件事；节奏像跟朋友聊天**。范例：普通人的 AI 课第 1–4 课的 `抖音-v2/`（17–18 帧，126–139 秒）。

核心有五条：

1. **一条只讲一件事**：一个翻车 + 一句话的解法。进阶招最多一个，避坑最多一条，其余放公众号
2. **先给原话，再给 AI 写的**：让观众自己看出问题，而不是直接告诉他「它错了」
3. **真实操作画面**（录屏、截图、原话）代替文字卡片；数字、截图、原话都来自实测记录，注明第几轮、是否倍速
4. **讲道理**：为什么（大白话）→ 类比 → 加一句话怎么改 → 改后的实测结果（来自费曼检查）
5. **一个画面讲一个意思**：一帧可以配好几句口播，说完再换画面，不急着切

## 结构：17–18 帧，一帧一个意思（可配几句口播）

| # | 段落 | 口播要做的事 | 画面（帧模板） |
|---|---|---|---|
| 1 | 钩子 | 结果 + 冲突，一两句 | 第 0 秒就有大画面：错数字（`Kit.number`）、原话 vs AI 写的（`Kit.compare`）、实测截图；`"kicker": false` |
| 2 | 开场 | 「这事你可能也干过。今天就跟你聊聊……」 | `title`：今天聊聊 + 两行大字 |
| 3 | 场景 | 先交代是什么事（谁、要干什么），再说细节 | `Kit.chat` 情景演绎，或 `Kit.stream` 逐行出原始材料 |
| 4 | 操作 | 我怎么问的 | `Kit.prompt` 打出提问，或录屏原速 |
| 5 | 结果 | 几秒出来，「看着挺像回事，对吧？」 | 录屏 + `timer` |
| 6–8 | 翻车 | 冲击帧一句 → 先给原话 → 再给 AI 写的，让人自己看出问题 | `ground: "accent"` 冲击帧；`Kit.stream` 原话；`Kit.answer` 重建回答并 `focus` 那一行；`Kit.shot` 截图圈出 |
| 9 | **为什么** | 「你想啊……」大白话 | `Kit.chain` / `Kit.compare`「你以为 / 其实」 |
| 10 | **类比** | 人人见过的东西 | `title`「打个比方」或手写小动画 |
| 11 | **方法** | 「其实就加一句话」 | `Kit.prompt` 打出那一句 |
| 12–13 | 方法结果 | 新对话再跑一遍的实测结果；只跑了一次就直说 | `Kit.compare` 前后对比 / `Kit.stream` 原话 |
| 14–15 | 进阶（可选，最多一个） | 一句追问 + 结果 | `Kit.prompt` + 截图 / 原话 |
| 16 | 避坑（最多一条） | 实测里真遇到的问题 | `Kit.compare` / `title` |
| 17 | 收尾 | 模板在评论区，复制就能用 | `Kit.template`（`keys` 标出那一句） |
| 18 | 下一课 | 一句预告 | `title` |

为什么、类比、方法三帧来自母稿的费曼检查（scenario-content 的 `费曼检查.md`），不能省。

## 关键镜头：手写小动画

整片大部分帧用帧模板（统一、省事），但**最需要「看懂」的一两帧**（通常是类比，有时是钩子）值得做成一段小动画：把比喻演出来，而不是写成字。第 1 课的对比：「只报总价的收银员」三行大字 vs 收银台屏幕只亮一个总价 + 大问号、带编号的小票打印出来并标出重复的两行，后者明显更好懂、更好看。

怎么做：
1. 在 STORYBOARD 里删掉这一帧的 `- build:` 行，`scene` 写清楚动画脚本（每个口播词出现什么）；`nv hf-frames` 不会覆盖没有 build 的帧
2. 手写 `compositions/frames/NN-*.html`：结构照抄帧模板生成的文件（根元素和它的抗锯齿样式、底色 clip、角标、`cues.js` + `kit.js`、`var C = …Kit.cue…`），颜色只用 `var(--kit-*)`
3. 动画规则不变：每个元素在说到它时出现（`C("词")`）；只有一个亮点动作；落定后静止；不回弹
4. 能用组件的部分直接用：`Kit.receipt`（打印小票）、`Kit.number`（数字滚动）、`Kit.marker` 等
5. `nv hf-build --motion` 看入场 / 中段 / 落定，`check` 必须 0 错误（会查文字重叠和对比度）

注意：
- 类比里的物品、金额是**示意**，不是实测数据；不要和实测数字混在同一个画面里让人误会
- 右侧 160px 是抖音按钮区，标签、箭头不要伸进去
- 一个视频最多 2 帧手写，其余用模板，保持整片风格统一

范例：第 1 课 `抖音/compositions/frames/07-receipt.html`（收银台）、`08-number.html`（`Kit.receipt` 小票）。

## 画面规则（每帧都要过）

借鉴 [chenyuxiaojin/cyxj-hyperframes](https://github.com/chenyuxiaojin/cyxj-hyperframes)（MIT）的硬约束和动效笔记、[nutllwhy/hyperframes-motion-library](https://github.com/nutllwhy/hyperframes-motion-library)（MIT）的导演规则，按我们的竖屏口播改写：

1. **画面是口播的延伸，不是字幕的翻译**：字幕已经在下面了，画面不要再把这句话原样写一遍。先问「这句话里的关键词长什么样」：「只报总价」→ 收银台屏幕只亮一个数；「列编号」→ 一张带编号的小票；「两次不一样」→ 两个结果并排。实在没有形象，才用大字（`title` / `marker`），且只写关键词，不写整句。
   **写每一帧前先问：这句话能画成什么动作？**「先把文件发给它」→ 文件飞进输入框（`attach`）；「别整本扔，挑几页」→ 一摞书打叉、抽出三页（`pick`）；「先这样、再那样」→ 步骤（`steps`）；「以前 vs 现在」→ 对比卡（`compare`）。大字、荧光笔、模板卡、打字这类**纯文字帧最多连着两帧**，`nv hf-frames` 连着三帧以上会警告（RAG 那期第 9–12 帧四张文字卡，观众觉得平；第 9、11 帧换成 `attach`、`pick` 后就有了画面）。
2. **不加口播和实测里没有的信息**：画面上的每个字、数字都要在口播或实测记录里找得到；不为了「填满」临时编小标题、编数据。
3. **内容待在四角框里**：glow 的四角框住内容区 y 200–1160（角标在 y 270 左右，内容从 y 330 往下排），字幕从 1180 开始。「下半屏偏空」的警告只能靠调布局解决，不能把东西撑出框：放不下就调小 `size`、少放一项。`nv hf-build` 的 check 会在每帧结尾查文字有没有伸到 y 1160 以下（`--caption-zone`），报错必须修；面板、图片不是文字，要自己看总览图。录屏帧铺满全屏是本来的设计。
4. **内容铺开**：落定时主体要铺满内容区（角标以下、字幕带以上），不要全挤在上半屏、下面空一大块。`nv hf-build --snap` 会量每帧的铺开程度，纵向不到 55% 的帧给出警告；处理办法：放大字号、把元素往下排开，或加一个和口播有关的图形（不是装饰）。
5. **落定后静止，不做退场**：元素在帧结尾前不淡出、不飞走，切换交给帧间转场；否则观众会看到「东西没了」的空画面。
6. **重点时刻一起命中**：每帧只有一个亮点动作（圈、划、数字落定、问号落下），它要和口播的那个词、音效在同一时刻（`C("词")` 对齐）；不要一个词拆成好几拍慢慢出。
7. **不剧透**：钩子只抛冲突和结果，不提前展示后面的方法、模板；方法帧之前不出现方法里的字。

另外，帧模板、组件和字幕的根元素都开了中文灰度抗锯齿（`-webkit-font-smoothing: antialiased; text-rendering: optimizeLegibility`），手写帧要照抄。

## 节奏、转场和镜头

学自官方发布视频的源码（[heygen-com/hyperframes-launches](https://github.com/heygen-com/hyperframes-launches)，Apache-2.0）：pr-to-video-launch（30 秒 10 个场景全部硬切）、claude-paper-launch 的 FRAME 规范、hyperframes-launch 的分镜和交接记录。

1. **默认硬切**：帧和帧之间直接切，靠每帧自己的入场动画接上。转场整片最多两三处，只放在**剧情转折**（「可第一次……」用 `push-slide`）和**收尾**（`crossfade`）。不要每帧都加转场，否则节奏会变得拖沓。
2. **长短交替**：大部分帧 3–4 秒，转折前后可以插一个 **1 秒左右的冲击帧**：一句话、居中、大字（`title` 加 `"center": true`），例如「两次不一样」「可它算错了」。官方用 0.9 秒的一行字把节奏拉紧。冲击帧要有自己的一句短口播。
3. **开场就在动**：第一帧第 0 秒就有东西在动（录屏在播、元素正在进来），不从空画面淡入。
4. **落定后也要在动**：静止的画面就是一张带进度条的图片（官方 Claude Design 指南的说法）。帧模板默认整帧缓推（推近 4%，角标不动），观众察觉不到「在动」，画面却不死；录屏帧、`Kit.shot` 帧自己在动，默认不推；确实要静止的帧写 `"camera": false`。glow 下底色光晕还会慢慢呼吸，但它太轻，只算氛围，不算「在动」。`nv hf-build --motion` 会比较每帧落定前 0.7 秒和落定两张图，几乎没差别就警告。
5. **版面别一直靠同一边**：官方规定连续最多两帧用同一种构图（靠左 / 居中）。我们的帧大多靠左上；冲击帧、结论帧可以用居中打破。
6. **一眼主次**：眯眼看，最重要的元素要比第二重要的大 3–6 倍；两个东西一样大，就降一个。
7. **结尾呼应开头**：收尾帧可以回到开头的画面或那句话（官方是镜头拉回第一幕的画布），让人有「讲完了」的感觉。
8. **动法要有性格**：同一帧里的元素别全用同一种缓动。组件已经按角色分好（见 `hf-kit.md`「缓动」）：主角（数字、换上的新词、大标题）`expo.out` 冲出来，弹出的小元素（勾、标签、注释）`back.out` 轻轻回弹，一般入场 `power3.out`，背景和镜头 `sine.inOut`。手写帧照这个分。
9. **特效转场（WebGL 着色器）以后要用时**：HyperFrames 有 14 种着色器转场。官方规则：整片最多两三处，只放在揭晓、情绪转折、收尾；按能量选（平静：`cross-warp-morph`、`light-leak`；中等：`cinematic-zoom`、`whip-pan`；强烈：`glitch`、`chromatic-split`）；时长不短于 0.3 秒，0.5 秒最好；转场前不做退场动画，转场就是退场。注意 `kit-glow.js` 的颗粒用的是 SVG 滤镜图片，官方说它在 Safari 预览里会让着色器转场失效（我们用 Chrome 渲染不受影响），真用时先验证。
10. **结尾不闪黑**：官方踩过子画面时间轴比分配时长短、结尾闪黑的坑。我们的版本（0.8.119）以帧时长为准，第 1 课逐帧查过没有黑帧；`nv verify` 也会查长于 0.5 秒的黑屏。

## 口播

- **钩子要说后果，不只说知识点**：「两次答案不一样」观众会想「所以呢」；「AI 数出了二十二条，你要是直接交上去……」说的是观众自己会踩的坑。后果用第二人称假设（「你要是……」），**不要编自己没经历过的情节**（如「我差点交给老板」）
- **钩子句式**（选一种，写成口语）：
  - 结果 + 后果：「二十条反馈，AI 数出了二十二条，你要是直接交上去……」
  - 结果反差：「同一个问题，我问了 AI 两遍，两次答案居然不一样。」
  - 速度反差：「两百条反馈，AI 八秒钟就分好类了。」
  - 翻车：「AI 信誓旦旦说不会错，结果还是错了。」
- 一帧的缩进块可以写好几行，每行一句，每句 ≤ 28 字；数字写汉字；用「你想啊」「对吧」「其实」这类聊天口吻；不自我介绍
- 口播里不出现观众不认识的人名（说「领导」「同事」），不堆实测细节
- 每句话都要和实测原文对得上：AI 原话里说「暂不确定，本次先不加」，就不能说成它「写成了定了」
- 情感：钩子惊讶、翻车惊讶、结果和收尾开心、方法平静
- 配音 `nv hf-audio . --speed 1.1 --pause 0.3`（1.1 倍速，帧间停 0.3 秒；1.0 + 0.5 用户觉得偏慢）；整条 2 分钟左右，不卡时长
- 画面里的标题大字一行 ≤ 9 个字，超过会折行和下一行重叠（`check` 报 content_overlap）；`Kit.prompt` / `Kit.stream` 要在帧结束前打完（`cps` / `rate` 调快），看 `snapshots/sheet.jpg` 每帧结尾那张

## 实测和素材（先于写稿）

1. 在真实产品里跑实测，用 `nv rec` 录下全过程，用时和页面全文写进实测记录
2. 关键结果截图（推近要看清的那一块，必要时先裁剪）。**手机上看得清才算证据**：截图里的字显示出来要 ≥ 36px，整张表缩在 960 宽里一般只有 25px，要用 `zoom` 推近或裁掉无关的列；裁剪只能去掉无关部分，不能拼接、改动内容
3. 同一个提问**跑两次**：结果不同本身就是好素材（「两次不一样」比「一次正确」更有话说）
4. 视频里出现的每个数字、截图、原话，都要能在实测记录里找到

## 帧模板（STORYBOARD 里写 `- build:`）

每帧在 STORYBOARD.md 写一行 JSON，`nv hf-build` 会自动生成画面（`nv hf-frames`）。时间写 `"@词"`（说到这个词时），不手写秒数。

**动画别挂在句尾的词上**：帧在这句话说完就切走，挂在最后一两个字上的动画来不及播完。荧光笔要 0.5 秒涂完、圈词注释要 1 秒才出来，尤其要挂到前面的词上（「回答之前，先去翻资料」挂 `@先去`，不挂 `@翻资料`）。`nv hf-frames` 会按逐字时间检查，来不及看清的会给出 ⚠。

```text
- build: {"rec":{"mediaStart":4.0,"rate":1.5,"dim":true},"kit":{"name":"compare","opts":{"bad":{"tag":"第 1 次","text":"合计 22 条"},"good":{"tag":"第 2 次","text":"合计 20 条"},"at":["@两遍","@不一样"],"size":72}}}
- build: {"rec":{"mediaStart":0.9,"chip":"DeepSeek 实测录屏"}}
- build: {"rec":{"mediaStart":3.3,"rate":2.4},"timer":{"value":8.7,"note":"实际用时 · 视频 2.4 倍速"}}
- build: {"kit":{"name":"shot","top":540,"opts":{"src":"assets/a.png","size":[1610,800],"caption":"第 1 次实测","zoom":{"x":1000,"y":190,"scale":2.2,"at":0.1},"marks":[{"x":1045,"y":283,"at":"@两遍","label":"又算了一次"}]}}}
- build: {"lead":{"text":"它的合计 → 我给的条数","top":600},"kit":{"name":"strike","top":720,"width":"auto","opts":{"from":"22 条","to":"20 条","inAt":"@二十二","at":"@可我","size":170}}}
- build: {"kit":{"name":"marker","top":640,"opts":{"text":"一定让它列编号","key":"列编号","inAt":"@一定","at":"@列编号","size":130}},"lead":{"text":"错没错，一眼就能看出来","top":860,"at":"@错没错"}}
- build: {"kit":{"name":"template","top":480,"opts":{"title":"提问模板 · 截图保存","lines":["你是一名【你的岗位】。"],"at":0.05}}}
- build: {"title":{"label":"下一课","lines":[{"text":"为啥 AI 写方案，","at":"@为啥"},{"text":"总是**一堆废话**？","at":"@总是"}]}}
- build: {"ground":"accent","lead":{"text":"DeepSeek 原话","top":440},"kit":{"name":"stream","top":520,"opts":{"text":"……","at":"@说好"}}}

**钩子帧优先用 `chat`**：把痛点演成上班族熟悉的聊天（默认标「情景演绎」）。**实测结果优先用 `answer`**（实测原文重建，字清楚、能推近到一行），只有要证明「真的跑过」时才放录屏或截图。项目配置 `hfKit.look: "glow"` 时所有帧自动带光晕底色、HUD 和玻璃卡片。

- build: {"kicker":false,"kit":{"name":"chat","top":300,"opts":{"title":"双十一筹备群","count":5,"height":820,"messages":[{"from":"刘总","text":"@你 十分钟后把会议纪要发群里","at":0.1},{"from":"我","me":true,"doc":{"title":"双十一筹备会纪要","tag":"AI 整理","head":["事项","负责人","截止"],"rows":[["提货点海报重做","阿杰","未明确"]],"mark":{"row":0,"col":1,"at":"@派给了"}},"at":"@AI"},{"from":"阿杰","text":"？？海报我啥时候认领的","tone":"bad","at":"@同事"}]}}}
- build: {"lead":{"text":"它踩了 **3 个坑**","top":300},"kit":{"name":"answer","top":400,"opts":{"source":"DeepSeek 原话 · 实测第 1 轮","blocks":[{"h":"二、待办事项"},{"table":{"head":["事项","负责人","截止时间"],"rows":[["……实测原文……"]]}}],"focus":{"row":2,"col":1,"at":"@抄错","note":"其实是「王姐」"}}}}
```

可用部件（可组合，按需写）：

| 部件 | 作用 | 参数 |
|---|---|---|
| `rec` | 录屏，放在角标下方 | `src`（默认 assets/rec.mp4）、`mediaStart` 从录屏第几秒开始、`rate` 倍速、`dim` 压暗、`chip` 左上标签 |
| `timer` | 录屏上的计时面板 | `value` 真实用时、`unit`、`note`（写明倍速） |
| `kit` | 一个组件 | `name`（strike number marker annotate shot stream prompt arrow compare template checklist steps chain）、`top`、`width`（默认 960，`"auto"` 不限宽）、`opts` 见 hf-kit.md |
| `lead` | 一行灰色说明 | `text`（`**词**` 强调色）、`top`、`at` |
| `title` | 大字标题 | `label`、`lines`（字符串或 `{text, at}`）、`top`、`center`（居中，冲击帧用） |
| `camera` | 镜头 | 不写 = 默认整帧缓慢推近（录屏帧、截图帧除外）；`false` = 这一帧不推 |
| `ground` | 底色 | `"accent"` = 整屏强调色（翻车帧，整片最多一次） |

录屏的 `mediaStart`：看 `nv rec` 输出的 `.json`，`sentAt` 是发送时刻、`doneAt` 是回答结束。原速播「粘贴 + 发送」从 `pastedAt - 0.6` 开始；加速播「输出过程」从 `sentAt` 开始，`rate ≈ (doneAt - sentAt) / 这一帧时长`。

表里放不下的画面，删掉这一帧的 build 行，手写 `compositions/frames/` 里的文件（`nv hf-frames` 不会覆盖没有 build 的帧）。
