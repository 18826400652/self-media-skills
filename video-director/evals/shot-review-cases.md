# 评审员校准用例（references/shot-review.md）

> 评审提示词也先写用例（公共仓库 `standards/prompt-engineering.md` 第 4 节）。拿已知作品给评审员打分，分数落在预期区间、该点名的问题都点到了，评审提示词才算可用。
> 来源：`docs/superpowers/specs/2026-10-19-shot-library-design.md` 第 6.3 节。

## 怎么跑

每条用例开一个**新的、独立的** general-purpose subagent（不带制作过程的上下文），prompt = `references/shot-review.md` 第一段 + 下表的输入。校准时只有一组内容，所以「内容耐受」写 N/A；横屏片子「抖音版面」也写 N/A。平均分只算有分数的维度。

素材准备（片子不入库，路径是 2026-10-19 校准时的位置）：

- 第 1 期 117 秒原版：`.dsh/qa-sample/抖音/renders/01-AI写周报.mp4`，seg-01 = 0–13.40 秒，seg-06 = 72.16–99.05 秒
- P0 版：`.dsh/attn-p0/抖音/renders/抖音.mp4`，seg-01 = 0–6.46 秒，seg-06 = 49.40–61.80 秒
- 回形针原片：mg-styles-15 的 `videos/19-paperclip.mp4`（作者终评 7.71）
- 故意做坏：P0 工程副本，seg-01 改成前 0.6 秒空屏、卡片下移压进字幕带、重点行不换行溢出卡片；`vd build --sample --no-music` + `vd render --sample`

每段用 `ffmpeg -ss … -to …` 切出来，再 `vd review-pack <片段> --out <目录>` 出素材包。

**结论（2026-10-19）**：评审员区分得开（做坏的 2.9 < 现有成片 3.6–4.7 < 回形针原片 7.0），点名的问题逐条核对都属实（包括所有成片右边 x 1072–1079 的 8px 黑边，之前没人发现）。它只是比我事先猜的区间整体严约 1.5 分。为了凑区间去放松提示词就是作弊，所以提示词不改。
过线标准随之按原意换算：spec 定的是"比参考片作者终评略高"，这个评审员给参考片 7.0，所以镜头过线 = **每个维度 ≥7.0、平均 ≥7.5**（明显高于回形针原片）。
