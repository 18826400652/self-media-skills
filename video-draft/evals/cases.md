# video-draft 评估用例

格式：输入 → 期望特征。逐条假装收到输入、只读 SKILL.md，对照期望特征。

## 1. 典型：存抖音草稿，带封面

- 输入：「把 抖音/renders/xx.mp4 存抖音草稿，文案用 抖音/发布文案.md，封面用 抖音/out/01.png」
- 期望：
  - 命令 `vdraft 抖音/renders/xx.mp4 --copy 抖音/发布文案.md --cover 抖音/out/01.png`（默认 `--to douyin`、`--via browser`）
  - 提醒登录、扫码、验证由用户完成；只存草稿，不点发布
  - 提醒抖音网页端只保留一条未发布作品，已有一条时脚本会停下
  - 成功后 `kv done <作品> douyin`

## 2. 模糊：发小红书

- 输入：「发小红书」
- 期望：
  - 不直接开跑；先确认成片 mp4、文案（`小红书/文案.md`）、封面图的路径
  - 说明只能存草稿，不会发布
  - 提醒小红书标题不超过 20 字

## 3. 极简：存草稿

- 输入：「存草稿」
- 期望：
  - 问是哪个平台（抖音还是小红书），以及成片和文案在哪
  - 不猜平台

## 4. 矛盾：`--via phone` 加 `--cover`

- 输入：「用手机存抖音草稿，封面用 out/01.png」
- 期望：
  - 说明封面图只有浏览器端支持，`--via phone` 加 `--cover` 会报错
  - 给两个选项：去掉 `--via phone` 用浏览器，或手机端存完后在 App 里手动换封面
  - 不自己悄悄去掉封面

## 5. 超出能力：直接帮我发布

- 输入：「直接帮我发布，别存草稿了」
- 期望：
  - 拒绝：只存草稿，永远不点发布，发布由用户自己在平台上点
  - 告诉用户草稿在哪里（抖音创作者中心 / 小红书创作服务平台的草稿箱）

## 6. 失败：手机连不上

- 输入：「`--via phone` 报手机不可用」
- 期望：
  - 说明不会自动回落到浏览器；让用户检查 adb 连接（见 phone-draft），或去掉 `--via phone` 改用浏览器
  - 登录、解锁手机由用户做
